# 造物所 Maker Console

员工后台位于 `/admin`。它读取现有 R2 项目、订单和千问调用日志，使用现有 D1 数据库保存员工权限、方案审核、Kit、零件、库存流水、售后工单及操作审计。经营指标只统计实际记录；确认销售额仅统计人工核对到账的订单付款。

## 首次启用

1. 保持现有 `DB` (D1) 和 `BUCKET` (R2) 绑定，应用 `drizzle/0001_maker_console.sql` 迁移。
2. 在服务端设置 `ADMIN_EMAIL` 为创始管理员的 ChatGPT 登录邮箱。多个邮箱以逗号分隔。该环境变量不能写进前端代码。
3. 用相同邮箱通过站点的 ChatGPT 登录入口登录，访问 `/admin`。管理员可在「员工权限」中添加技术、运营和客服人员。员工首次登录后，其 ChatGPT 用户 ID 将绑定至员工记录。
4. 普通用户及无授权的 ChatGPT 账号访问管理 API 会被拒绝。员工停用后，原登录会立即失去管理权限。

本地预览可将测试邮箱写在不提交的 `.dev.vars` 中。`QWEN_API_KEY` 仍只由原有服务端 AI 请求读取，后台 API 不返回它。

## 第一版能力与边界

- 方案审核：保留原始 AI 方案，通过 D1 审核记录覆盖展示字段；区分生成、工程审核及实物验证。版本与原因留痕，审核结果同步到用户项目读取接口。
- Kit 与零件：独立的 D1 目录；BOM 成本按当前零件采购成本计算。库存入出库有流水，不能出库至负数。新 Kit 目录目前属于员工管理目录，用户站现有静态展示尚未接入该目录。
- 定制订单：沿用用户站的 R2 订单快照。员工可确认报价、人工付款核对、更新状态及物流单号；无已核实付款时无法配货或发货。尚无标准 Kit 下单、自动配货、快递接口与退款集成。
- 用户：列出本地邮箱账号及产生过项目或订单的用户。纯 ChatGPT 登录且尚无业务记录的账号无法从当前存储完整枚举。
- 售后：用户可在制作指导页提交文字工单并查看公开回复；员工可查关联项目摘要、回复、备注、设置优先级和负责人。图片上传与 AI 自动转人工尚未接入。
- AI 日志：读取既有 R2 调用记录，可按模型、任务、项目及用户哈希标识搜索。费用是估算；实际账单以模型服务商为准。旧记录可能没有项目 ID。
- 列表：支持搜索、适用模块的状态筛选和分页。R2 扫描最多读取 5000 条并显示截断提示；付款列表沿用现有 200 条读取上限，审计列表为最近 100 条。

提示词版本、模型路由配置、额度管理、库存预留、项目模板版本和高级数据分析属于后续阶段；页面没有将它们伪装为已上线功能。

## 验证

运行 `node --test tests/admin.test.mjs tests/ai-design.test.mjs tests/payments.test.mjs`、`node node_modules/typescript/bin/tsc --noEmit` 和 `node scripts/run-framework.mjs build`。测试覆盖权限隔离、审核同步、库存流水、BOM 成本、报价、未付款发货拦截和售后工单。
